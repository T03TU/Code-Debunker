# Sandboxed Test Execution & QA Gating Skill

## Part 1: Isolated Sandbox Test Execution
When executing unit tests generated by `@dataflow-test-synthesis`:
1. Write the target source module and generated test file into an ephemeral staging directory, then mount it read-only (`/workspace:ro`) into a hardened Docker runner container obeying `.agent/rules/security-sandbox-guardrails.md`.
2. Execute the language-appropriate test runner with structured JSON output enabled:
   - **Python:** `pytest --json-report --json-report-file=/tmp/report.json /workspace/test_target.py`
   - **JavaScript / TypeScript:** `npx jest --json --outputFile=/tmp/report.json /workspace/target.test.ts`
3. **Self-Correction Loop (Max 2 Retries):**
   - If the test runner fails due to a **test harness error** (e.g., `ImportError` on an unmocked third-party package, `TypeError` in mock setup, or syntax error in the generated test), pass `stderr` back to `@dataflow-test-synthesis` to repair `test_code` and re-run.
   - **Never** alter the user's source code to make a test pass. If the failure stems from a bug in the user's logic, record the failing assertion, line number, and runtime values.
4. Map test outcomes (`PASS`, `FAIL`, `ERROR`) and captured intermediate values onto the matching `symbol_id` and `edge_id` entries in the JSON IR.

## Part 2: Output Quality Assurance (QA) Gate
Before finalizing any response or API payload, verify every item in this checklist:

- **Target Anchoring Check:** Confirm that the Feynman explanation, annotated code, UML root node, and unit tests all target `target_symbol_id` rather than an adjacent helper function.
- **Pedagogical Completeness Check:**
  - Verify all 5 required sections are present (`Language Identification`, `Feynman Explanation`, `Annotated Code`, `Simulated Execution Walkthrough`, `Prerequisite Concepts`).
  - Audit the docstring inside `Annotated Code`: reject summary-only docstrings. Every parameter (including optional flags and defaults), every nested dictionary key, every tuple return element, and any raised exceptions must be explicitly documented.
- **UML Span Integrity Check:** Verify that 100% of emitted UML nodes and data-flow edges contain valid, non-null `span` integers (`start_line <= end_line`) matching the JSON IR.
